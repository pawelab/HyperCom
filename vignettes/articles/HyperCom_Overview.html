Inputs

HyperCom requires three inputs. Most failed runs come from one of these points, so check them first:

  1. Counts: a gene x cell matrix with genes as row names and cells as column names, sparse or dense. Raw or normalised counts give the same results, since HyperCom only uses whether each gene is above 0 in each cell; never use scaled data (negative values stop the run). Cell names must be unique across samples: prefix the barcodes with their sample when merging samples.

  2. Cell metadata: a dataframe with one row per cell, its row names being the cell names of the counts, with a sample column and optionally a group column. The sample is the library or replicate: cells are only compared with cells of their own sample, so every sample needs at least 2 cells that express a ligand or receptor gene. The group is the condition, for priorities specific to a group. Cells of the counts without a row in the metadata are left out, with a warning.

  3. Ligand-receptor (LR) interactions whose gene symbols match the species of the counts. HyperCom contains 2 built in LR databases formatted properly:

    • CellChat human cellchat.hs.lrdb (gene symbols such as TGFB1)

    • CellChat mouse cellchat.mm.lrdb (gene symbols such as Tgfb1)

Running HyperCom

The whole pipeline runs with one call to HyperCom. It writes every step to outdir and returns the results as a list, so they need not be read back. parallel=TRUE uses one thread per physical core and threads sets the number directly (the default is one thread). significance=TRUE adds p-values and seed makes them reproducible.

outdir <- file.path(tempdir(), "overview")
res <- HyperCom(lrdb=cellchat.mm.lrdb, counts=alexanian2021.counts,
                metadata=alexanian2021.metadata, sample="sample",
                group="condition", significance=TRUE, seed=1,
                parallel=TRUE, outdir=outdir, verbose=FALSE)

                       assay="RNA", layer="counts", group="condition",

Run time and memory

Memory grows with the number of cells per sample squared, since cells are compared within their sample: more samples of the same size cost little. Measured with parallel=TRUE on 16 threads:

cells samples time memory
1,000 (this vignette) 2 seconds under 1 GB
20,000 3 about 1.5 min about 3.5 GB
50,000 3 about 28 min about 19 GB

The influence matrix is never built in full by default, so its memory grows with the number of cells rather than its square. infmat.method="lu" builds it in full and reproduces the numbers of HyperCom 0.0.0.9000 exactly (the default agrees with them to about 1e-15), at the cost of two matrices of all cells and genes squared.

Running HyperCom step by step

The rest of this vignette runs each component function of the pipeline in turn, with outfile=NULL so nothing is written.

Preprocessing

In order to reduce memory usage, we first filter the counts matrix to only genes present in the LR interactions with expression greater than 0. The function also transposes the matrix.

lr.counts <- filter_counts(counts=counts, lrdb=lrdb, outfile=NULL)
dim(lr.counts)
[1] 1000  663

Next we filter the ligand receptor interactions to only interactions where all genes are present in the filtered expression matrix.

lrs <- generate_lrs_table(counts=lr.counts, lrdb=lrdb, outfile=NULL)
dim(lrs)
[1] 1042    5

Generating Hypergraph

To generate the hyperedges, which are edges that contain multiple nodes, we use the expression matrix and the LR interactions to create 2 types of hyperedges:

  1. expression edges - edges containing a ligand or receptor gene and the cells that express it

  2. interaction edges - edges containing the genes that comprise an LR interaction

HyperCom represents these hyperedges as a dataframe with an edge and node column where the node belongs to the edge. The weight is set to 1 for each edge.

hyperedges <- generate_hyperedges(counts=lr.counts, lrs=lrs, outfile=NULL)
head(hyperedges, 2)
# A tibble: 2 × 3
  edge                node   weight
  <chr>               <chr>   <dbl>
1 TGFB1_TGFBR1_TGFBR2 Tgfb1       1
2 TGFB1_TGFBR1_TGFBR2 Tgfbr1      1

We can represent this hypergraph as an adjacency matrix where the nodes are the cells, ligand genes, and receptor genes. Each entry is the number of hyperedges shared by nodes. The matrix is not stored: adj keeps which nodes are in which hyperedge, which is much smaller, and works like a matrix (dim(adj), adj[i, j], as.matrix(adj) for the whole matrix).

adj <- generate_adjacency_matrix(hyperedges=hyperedges, outfile=NULL)
dim(adj)

  Sdc4                   0                  0                  0

Calculating Network Connectivity

In order to calculate the network connectivity of the hypergraph we perform a random walk with restart on the adjacency matrix to produce an influence matrix: entry (i, j) is the share of a walk started at node i that ends at node j, so each row sums to 1. At every step the walk returns to its start with the restart probability r, so about r of each node’s influence stays on the node itself and the rest spreads over the nodes it shares hyperedges with. generate_infMat takes r (default 0.5); HyperCom always uses 0.5. On this example the ranking of LR pairs hardly depends on it: r = 0.1 and 0.8 give the same top 20 pairs as 0.5. Like the adjacency matrix, the influence matrix works like a matrix without being stored in full.

infMat <- generate_infMat(adj=adj, r=0.5, outfile=NULL)
dim(infMat)
[1] 1663 1663
infMat[c("Thbs1", "Sdc4"), 1:3]

Downstream Analysis

Identifying Important LR Pairs

We can also identify important LR pairs by using HyperCom scoring on LR pairs. This prioritization scores LR pairs to find highly communicative LR pairs that are optionally group specific. The priority of a pair is the weighted geometric mean of five terms of the cells that express its genes: their fraction of all cells, the smallest fraction of cells expressing one of its genes, the mean of each cell’s larger score as sender or receiver, how evenly they split into senders and receivers, and how much they concentrate in some groups. The weights arg sets how much the fraction of cells counts: 1 (the default) weighs it like the other terms and smaller values favor pairs specific to fewer cells; a vector of weights gives one result each.

priority <- prioritize_lr(lrs=lrs, adj=adj, infMat=infMat, metadata=node.meta,
                          weights=c(1, 0.5), parallel=TRUE, outdir=NULL,
                          verbose=FALSE)
head(priority[["1"]])

The result has one table per weight, with the columns of the LR table and the priority. With significance=TRUE, as in the HyperCom call above, it also has p and p.adj: p is the fraction of 1000 background pairs of random genes whose priority is at least as high, so it moves in steps of 0.001 and 0 means none was as high (background pairs that get no priority are left out, with a warning); p.adj is its Benjamini-Hochberg adjustment. This takes about four times as long.

Scoring Cells

We see that Thbs1-Sdc4 is the highest scoring LR pair. We can calculate HyperCom scores for this pair. Each pair of cells i and j of a sample is scored by how strongly cell i reaches the ligand and the receptor reaches cell j, relative to how strongly i reaches j; these scores are percent-ranked together. A cell’s sender score is its average rank as cell i and its receiver score its average rank as cell j (between 0 and 1); dif is receiver - sender, avg their mean and max the larger. The HyperCom score hypercom is the sign of dif times the percent rank of its size among the cells times avg: negative for senders, positive for receivers. Cells with no path to the pair’s genes get NaN.

Thbs1_Sdc4 <- score_hypercom(infMat=infMat, metadata=node.meta, ligand="Thbs1",
                             receptors="Sdc4")
